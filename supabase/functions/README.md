# functions/

Edge Functions. Each one validates input, returns generic errors, and checks the
caller before acting.

| Function          | Step | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ----------------- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `member-login`    | 3.1  | Member ID or profile email + password sign-in (an email is turned into its member ID only when exactly one member uses it). Public (no JWT): protected by Turnstile (verified by Auth), lockout per ID and per address, origin check, generic errors. `handler.ts` holds the rules and is unit-tested (`tests/unit/member-login.test.js`); `index.ts` wires the Supabase clients.                                                                                                                                                                                                                                   |
| `member-import`   | 3.2  | Creates member accounts from the spreadsheet and the first admin. Server-to-server: called by `scripts/import-members.mjs` and `scripts/create-admin.mjs`. Access: a signed-in user with `members.import`, or a temporary bootstrap token (secret `IMPORT_BOOTSTRAP_TOKEN`). The token is removed after use; to import again, create a new random token, set it with `supabase secrets set --env-file <file outside the repo>`, keep a copy outside the repo, and unset it afterwards. The rules are in `_shared/member-import-rules.ts` (unit-tested in `tests/unit/member-import.test.js`).                       |
| `member-password` | 3.4  | Changes a signed-in member's password: policy (12+ characters, nothing built from the ID, birth date or first password), recent-session check, throttle, then clears the forced-change flag and signs out other sessions. Policy in `_shared/password-policy.ts`, tests in `tests/unit/member-password.test.js`.                                                                                                                                                                                                                                                                                                    |
| `member-signup`   | 3.3  | Public sign-up for new members only. Allowed origins only; Turnstile checked through Auth (a sign-in probe with an address that cannot exist: `invalid_credentials` means the token was good); honeypot field; 10 attempts per address per hour; strict validation and the password policy; assigns the next member ID; creates the account, a `pending_approval` member with only the pending role, the waiver and privacy consents, and review flags (possible duplicates, minors). A request that names a member ID is refused. Rules in `_shared/signup-rules.ts`, tests in `tests/unit/member-signup.test.js`. |

Deploy (no Docker):
`npx supabase@2.118.0 functions deploy <name> --use-api --project-ref <ref>`.
